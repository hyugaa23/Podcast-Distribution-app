# Beta QA — 16 Oktober 2026

**Keputusan: belum siap open beta.** Alur publishing inti berjalan, tetapi registry distribusi, data demo, dan acceptance test backend perlu dibereskan. Closed beta kecil dengan pendampingan lebih masuk akal setelah blocker P1 ditutup. Audit keamanan tidak dilakukan.

## Yang benar-benar diuji

- Live: `https://admin.podcastdistribution.net` dan sepuluh website/tema, termasuk `podcastdistribution.net`.
- Browser: 23 halaman admin utama + 5 halaman detail; 33 tab admin; 80 URL publik (home, podcasts, episodes, categories, hosts, collections, about, search).
- Browser publik: memulai/menghentikan player, seek, speed pada tema yang menampilkannya, gambar, dan homepage mobile 390px. Tidak ditemukan gambar gagal pada pemeriksaan tersebut; homepage sepuluh tema tidak overflow horizontal.
- Data QA terpisah: membuat/mengedit website, domain, branding/about/SEO, kategori, host, podcast, episode, collection, redirect, platform, user, API key; mengubah status distribusi dan membaca history.
- Audio MP3 8 detik: signed upload → worker FFmpeg READY → schedule/reschedule → unpublish → preview → transcript → publish episode dan parent podcast.
- Artwork PNG 1400×1400: upload dan processing; RSS setelah artwork valid, enclosure tersedia, feed publik HTTP 200, RSS import preview membaca satu episode.
- CSV import, empat ekspor CSV, analytics, audit, jobs, logs, metrics, dan metadata backup.
- Akun/konten QA sementara dibersihkan; audit trail pengujian dipertahankan. Tidak mengubah konten/demo existing untuk membuat hasil terlihat lebih baik.
- Provider AI transcription, pengiriman webhook end to end, RSS import/sync penuh (yang diuji adalah preview), ownership DNS domain baru, dan submission nyata ke akun Spotify/Apple/YouTube/Podcast Index **belum divalidasi**. Membuka portal atau mengganti status manual bukan bukti listing berhasil.

## Bug yang diperbaiki

1. **P1 — Backup produksi gagal.** `podcast-backup.service` gagal pada 14–16 Oktober: postgres tidak dapat melewati `/opt/podcast`. Lokasi dump dipindah ke `/var/backups/podcast-platform`; timer existing dipertahankan. Dump baru berhasil, `pg_restore --list` membaca 369 baris. Restore penuh ke PostgreSQL terisolasi juga berhasil: 10 website, 19 podcast, 66 episode; database hasil drill dihapus sesudah verifikasi. Unit yang dapat direproduksi: `infrastructure/systemd/podcast-backup.service`.
2. **P1 — Wizard distribusi rusak di mobile.** Di viewport 390px, halaman live melebar sampai 589px karena grid tetap `260px 1fr`. Grid kini menumpuk di mobile dan kolom detail boleh mengecil; regression browser 390px lolos.
3. **P1 — Preview menampilkan edit lama.** Tombol Preview meminta token tanpa menyimpan draft yang sedang diedit. Sekarang save selesai sebelum token dibuat; kegagalan save menutup popup kosong. Urutan request diverifikasi di browser.
4. **P1 — Network error saat refresh sesi menjadi unhandled rejection.** AuthProvider sekarang menangani kegagalan refresh dan menyelesaikan inisialisasi. Login tetap dapat digunakan; diverifikasi dengan request refresh yang sengaja diputus.
5. **P1 — Refresh sesi bisa menunggu tanpa batas.** Request refresh kini memiliki timeout 30 detik. Refresh bersamaan tetap memakai satu request untuk menjaga rotasi cookie.
6. **P2 — Token kedaluwarsa tertinggal setelah refresh ditolak.** Token di memori sekarang dibersihkan jika refresh gagal dengan respons non-OK.
7. **P2 — Error ekspor kehilangan pesan backend.** Mode raw mengembalikan response gagal sebelum parsing error. Kini raw hanya untuk response berhasil; error CSV mempertahankan status/kode/pesan backend.
8. **P2 — Upload batal/timeout dapat menggantung indikator.** XHR kini memiliki timeout 30 menit dan handler abort/timeout yang menyelesaikan promise dengan pesan yang jelas.
9. **P1 — Preferensi player rusak dapat merusak inisialisasi audio.** Volume disimpan di luar rentang dan speed negatif dapat memicu exception browser. Volume sekarang dibatasi 0–1; speed harus anggota pilihan yang didukung.
10. **P2 — Penolakan play lama dapat menimpa lagu baru.** Callback error sekarang memeriksa apakah track yang meminta play masih aktif; kegagalan play juga menghentikan buffering.
11. **P2 — Close player meninggalkan state lama.** Close kini membersihkan error, buffering, timer seek, dan metadata lock screen.
12. **P2 — Field nomor episode mengizinkan nol.** Form baru/editor sekarang memakai minimum 1 dan step 1, sesuai aturan backend.
13. **P1 — Bulk selection terbawa saat ganti website.** Pilihan podcast/episode, hasil bulk, dan pagination direset saat scope berubah. Filter podcast episode juga direset; tombol bulk tidak aktif ketika data sedang dimuat. Dua alur diuji di browser.
14. **P1 — Versi Go tidak sesuai dependency.** Working tree semula memakai Go 1.23, dependency meminta ≥1.26; commit sebelumnya bahkan meminta 1.27.1. Manifest dan image build sekarang konsisten dengan Go 1.26; `go test ./...` berhasil dengan toolchain 1.26.0. Go sistem VPS masih 1.23.2; toolchain 1.26 dipakai secara eksplisit untuk verifikasi.

15. **P1 ? Header admin overflow dengan domain panjang.** Setelah grid wizard diperbaiki, selector website di header masih membuat viewport 390px melebar menjadi 434px pada data live. Lebar label/select kini dibatasi container mobile; fixture regression memakai domain panjang, bukan hanya nama pendek.

## Temuan yang masih terbuka

16. **P1, live — Empat pasangan platform duplikat.** `apple`/`apple-podcasts`, `youtube`/`youtube-music`, `amazon`/`amazon-music`, `podcastindex`/`podcast-index`. Migration 0003 dan seed memakai key berbeda. Registry live mempunyai 19 platform, sehingga checklist/progress juga dihitung dengan denominator yang membengkak. Perlu migration konsolidasi yang mempertahankan listing, history, dan kompatibilitas key lama; jangan menghapus platform berisi data secara paksa.
17. **P1, test nyata — Acceptance test backend gagal.** `TestE2E` pada PostgreSQL + Redis terisolasi berhenti di `e2e_test.go:507`: `distribution dashboard: live 0 total 20` sedangkan assertion mengharapkan 14. Selain duplikat, test masih memakai jumlah registry lama. Jangan sekadar melonggarkan assertion; perbaiki seed/registry dan uji tidak ada duplikat sebelum menjalankan seluruh acceptance flow kembali.
18. **P1, live — Dashboard kesehatan melewatkan kegagalan backup.** Saat unit backup failed, dashboard tetap menampilkan “No critical failures”. Tambahkan status keberhasilan backup terakhir, umur dump, dan alert jika timer gagal/backup terlambat.
19. **P1, live — Analytics demo bercampur dengan angka operasional.** Dashboard menampilkan sekitar 2.500 plays dan breakdown berisi banyak domain `.localhost`. Angka ini tidak dapat dipakai sebagai bukti traction/live user. Pisahkan tenant/event demo dari laporan beta dan beri label demo pada seluruh statistik contoh.
20. **P1, live — Status distribusi contoh belum membuktikan listing nyata.** Ada 25 issue pada baseline dashboard; sejumlah Pocket Casts listing menghasilkan 404. Pisahkan seed/demo listing dari data pengguna dan gunakan URL valid + timestamp verifikasi untuk mengklaim LIVE.
21. **P1, pemeriksaan kode — Ukuran artwork gagal tetapi readiness bisa tetap lulus.** `DistributionReadiness` hanya menambahkan detail ketika artwork diketahui tidak persegi atau di luar 1400–3000px; `items[2].Passed` tidak diubah menjadi false. Tambahkan regression dengan artwork kecil/tidak persegi sebelum memperbaiki dan merilis backend.
22. **P2, pemeriksaan kode — Batas upload tidak konsisten.** AudioCard menerima sampai 1GB, backend default 500MB dan dapat dikonfigurasi. UI perlu membaca limit efektif dari API; jangan menggantinya dengan hardcode lain.
23. **P2, pemeriksaan kode — Timeout RSS preview lebih pendek dari proses backend.** Client umum timeout 30 detik, handler preview memberi waktu fetch 45 detik. Feed lambat bisa ditampilkan gagal walau backend belum selesai. Selaraskan timeout khusus dan tambahkan cancel/retry yang jelas.
24. **P2, pemeriksaan kode — Mengosongkan publish date tidak tersimpan.** `toBody` mengirim `publish_date` hanya bila truthy; menghapus nilai lama tidak mengirim perubahan. Butuh kontrak clear/reset yang eksplisit di API dan regression editor.
25. **P2, pemeriksaan kode — Source scheduling menolak reschedule.** `ScheduleEpisode` source hanya menerima DRAFT/PROCESSING, sementara UI masih menawarkan schedule dan binary live berhasil menerima reschedule. Ini risiko regresi jika binary backend diganti langsung dari source sekarang.
26. **P2, pemeriksaan kode — Newsletter belum merupakan newsletter.** Pada Business/Minimal, section newsletter hanya menampilkan social links; konfigurasi button label/link di admin tidak menghasilkan subscription. Hubungkan ke URL/form provider atau ubah label admin menjadi follow/social.
27. **P2, pemeriksaan kode — Analytics mempertahankan filter podcast saat ganti website.** `podcastId` tetap memakai pilihan website sebelumnya. Reset filter saat scope berubah dan uji query tenant + podcast yang dihasilkan.
28. **P2, pemeriksaan kode — Copy RSS gagal tanpa feedback.** SubscribeButton mengabaikan exception clipboard. Tampilkan kegagalan dan tetap sediakan input terpilih untuk copy manual.
29. **P3, live — Kontrol player berbeda antar tema.** Minimal menyembunyikan selector speed pada pemeriksaan desktop, sementara tema lain menampilkannya. Tentukan minimum fitur player yang konsisten atau sediakan menu tambahan.

## Masukan pengguna skeptis dan investor

30. **P1 — Klaim distribusi harus sesuai kenyataan.** Tulis jelas mana assisted/manual submission, mana API, dan mana listing yang sudah diverifikasi. Hindari kesan satu klik otomatis ke semua platform.
31. **P2 — Onboarding perlu satu jalur selesai.** Website → domain → show → audio → publish → RSS → platform, dengan next action dan error yang dapat ditindaklanjuti. Saat ini banyak langkah tersebar di menu berbeda.
32. **P2 — Pemulihan akses masih bergantung pada admin.** Tambahkan invitation/reset password sebelum beta melibatkan pengguna yang tidak didampingi founder. Ini kebutuhan operasional pengguna, bukan hasil audit keamanan.
33. **P2 — Beri feedback untuk pekerjaan async.** Setelah import/upload, tampilkan job yang dapat dibuka, status terakhir, alasan gagal, dan retry; jangan hanya toast “queued”.
34. **P2 — Tegaskan definisi analytics.** Player website sendiri berbeda dari total pendengar Spotify/Apple. Tambahkan penjelasan sumber data dan interval agregasi; klaim “real-time” perlu sesuai delay worker.
35. **P2 — Ukur beta dengan data nyata.** KPI awal: activation sampai feed valid, waktu ke publish pertama, upload/processing failure, RSS availability, serta pengguna kembali minggu berikutnya. Jangan mencampur seed, kunjungan QA, dan user beta.
36. **P2 — Mulai cohort kecil.** Setelah P1 ditutup, jalankan 5–10 creator dengan pendampingan dan jalur laporan bug yang jelas sebelum membuka pendaftaran umum.
